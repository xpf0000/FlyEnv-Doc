# Quality Gates

A FlyEnv Solution page is not ready until all applicable gates pass.

## Intent

- [ ] The page has one clear primary search intent.
- [ ] The intent is meaningfully distinct from any existing Guide.
- [ ] The H1 describes the solution/environment, not merely “How to run X” when a Guide owns that intent.

## Specificity

- [ ] At least 2–3 primary sections are technology-specific in content or visual structure.
- [ ] The page explains the technology's real local architecture or workflow.
- [ ] Generic framework/product introduction is minimal.
- [ ] Generic “common use cases” are absent unless they change the local environment story.

## Product grounding

- [ ] FlyEnv claims describe real current capabilities.
- [ ] At least one important proof element exists: real UI, workflow, result, architecture, or service topology.
- [ ] Product terminology matches FlyEnv's actual terms (for example, `Startup Group` if that is the product term).
- [ ] Screenshots and diagrams are technically coherent.

## Structure

- [ ] Sections were chosen from project needs, not copied as a fixed sequence.
- [ ] Repeated sections do different jobs rather than restating the same stack/features.
- [ ] Comparison exists only when it helps a real decision.
- [ ] FAQ exists only when there are meaningful unanswered questions.
- [ ] The page does not become a duplicate step-by-step Guide.

## Name Replacement Test

Temporarily replace the technology name with a substantially different one.

**Pass condition:** at least 2–3 primary sections become clearly wrong, irrelevant, or structurally inappropriate.

If most sections remain valid after swapping names and nouns, the page is template-driven. Redesign before finishing.

## Cross-page diversity

When editing several Solution pages:

- [ ] Do not use the exact same primary-section sequence by default.
- [ ] Do not use the same visual component set by default.
- [ ] Neighboring pages show different structures when their runtime models differ.
- [ ] Consistency comes from the FlyEnv design system, not repeated information architecture.

## Final question

Can a developer skim this page and understand **why this specific technology behaves differently inside FlyEnv**?

If not, the page is still too generic.
