## 4. 发现的问题

以下优先级表示建议收尾顺序，不代表均已造成线上事故。

### 4.1 P0：当前暂存区不能形成完整提交

**证据**

- `git diff --cached --stat` 只显示 12 个新增文件、1,342 行被暂存。
- 已暂存内容包括五份 SEO 文档、`ComparisonMigration.vue`、两个 Compare migration 数据文件、`solution-workflows.ts`、ZH/ID 404 和 `tests/analytics.test.mjs`。
- 大量配套现有文件修改没有暂存，包括组件接入、五语内容、主题、分析封装和其他页面。

**影响**

当前工作区整体可以构建，不代表暂存区可以独立构建。若直接提交暂存区，会形成“新文档、数据、组件和测试已提交，但实现接入及配套修改未提交”的不完整提交，存在编译或运行失败风险，也会严重破坏后续回滚和审查。

**建议**

提交前按任务组核对完整变更集，确认每个新组件的引用方、每个数据文件的消费者、五语内容和测试处于同一可构建提交中。不要只依据工作区测试通过就提交现有 staged snapshot。

### 4.2 P1：五语 Laravel 面包屑遗漏

`docs/components/LaravelSolutionPage.vue:14` 的首页链接固定为 `href="/"`，而同组件的 Solutions 链接已经使用 `localizedHref()`。

真实 Chrome 在 ZH、ID、ES、VI 的桌面和手机视口共复现 8 次：点击面包屑中的 FlyEnv 都回到英文首页。英文页正常。

这是已有代码问题，并非本次新增 diff 引入的回归，但属于本任务五语 Solution 范围内未覆盖的遗漏。应改为本语言首页链接，并补四个非英文语言版本的点击回归测试。

### 4.3 P1：关键行为缺少持久化回归测试，浏览器验收不易复现

`tests/analytics.test.mjs:10-89` 只有 4 个直接函数级测试，使用简化 `window` / `document` 替身，没有 DOM 点击或组件渲染。因而以下行为即使回归，当前 52 项测试仍可能全部通过：

- 安装包分类、外部供应商下载链接排除、尾斜杠 License 链接；
- 下载或许可导航的双事件及防重；
- 购买按钮可用状态与点击意向；
- Demos deep-link surface、播放器打开及内容组件实际交互。

新增 Compare migration 和 Solution workflow 也没有持久化内容完整性测试。现有 SEO 测试能覆盖构建元数据等结果，但不能替代上述行为测试。

建议优先补少量高价值 DOM/组件测试，而不是单纯增加函数断言数量；同时将本次 Chrome 验收整理为可复跑脚本，至少覆盖五语关键 CTA、下载、许可、Demos 深链和隐私拒绝路径。

### 4.4 P1：本次检查范围内 Prettier 未通过

对以下 10 个改动文件执行 Prettier check，均报告需要格式化：

- `docs/components/ComparisonMigration.vue`
- `docs/data/compare/migrations.ts`
- `docs/data/compare/stack-migrations.ts`
- `docs/data/solution-workflows.ts`
- `docs/components/CompareIndexPage.vue`
- `docs/components/AppSolutionDetail/en.vue`
- `docs/components/LaravelSolutionPage.vue`

- `tests/analytics.test.mjs`

其中前四个新增实现文件和新增 analytics 测试可明确算作本次交付的格式问题。该问题未影响本次构建，但意味着不能宣称完整质量门禁全绿。只应格式化本任务涉及文件，避免无关全仓格式变更。

### 4.5 P2：Solution 角色文案依赖数组下标，存在静默错配风险

`docs/components/AppSolutionDetail/en.vue:624` 使用 `roles[index]` 覆盖技术栈组件的角色说明；`docs/data/solution-workflows.ts:4-13` 将 `roles` 定义为字符串数组，并用宽泛的 `Record<string, ...>` 保存工作流。

后续如果调整 `solution-details.ts` 中 stack 的顺序、增删组件，角色文案可能静默套到错误组件上。当前未观察到实际错配，因此这是可维护性风险，不是已发生的内容错误。

建议按稳定组件 key 映射角色，并增加五语角色数量、key 完整性和目标组件一致性测试。

## 5. GA4 专项结论

专项代码审查未发现阻断、高或中严重度缺陷，没有证据支持敏感数据泄漏、生产初始化失效或关键转化误分类。

实现中有明确支撑的部分包括：

- 只在生产官网 origin 初始化；
- SPA 路由手动发送规范路径的 `page_view`，config 禁止自动首屏；
- URL 与 referrer 清理，保留有限公开 UTM；
- DNT/GPC 和支付返回页抑制；
- 下载、GitHub 等事件防重及包级元数据；
- 历史事件与新增 `*_nav_click` 同时发送是规范明确设计，不是意外重复，报表不得将二者求和。

仍需 GA4 管理员或部署负责人完成：关闭增强型历史浏览以避免重复页面浏览，审查自动 `file_download`、站内搜索、表单和出站事件，配置数据遮盖及自定义维度，在测试属性/DebugView 验收，并核对部署端 CMP/consent 是否依赖旧初始化顺序。

CDN 301、客户端 UTM、真实支付、安装和激活归因仍是独立外部任务。当前实现不能证明实际付款、安装成功或 SEO 收入贡献。
