# Local Codex Execution Notes

## Recommended access
Codex should have access to the complete website repository and, ideally, FlyEnv product source code or a reliable local mirror of product/module definitions.

If the website and app source are separate repositories, provide read access to both or export a current product-capability inventory into the website repo.

## Web access
Feature pages can largely be produced from local evidence.
Compare pages benefit strongly from current web access because competitor capabilities, license terms, platform support, and positioning can change.

If Codex cannot access the web:
- do not guess competitor facts;
- provide official competitor docs as local reference material;
- or pause Compare implementation until current research is available.

## Human review gates
Recommended approvals:
1. Feature inventory/category approval.
2. First 3 Feature pages.
3. First Compare page.
4. Features index visual/IA review.
5. Phase-1 final content review.

## Git workflow
Recommended:
- one branch per batch
- maximum 3 pages per batch
- descriptive commits
- include spec/research artifacts in the same branch/PR
- do not combine broad unrelated site refactors with SEO-page production

## Measurement
After pages gain search data, feed GSC/Semrush exports back into a review iteration.
Prefer improving pages already receiving impressions before endlessly expanding page count.
